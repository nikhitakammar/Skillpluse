# Skill Pluse demonstration guide

This walkthrough is designed for a five-minute presentation. The database, learner names, activity records, model labels and all metrics are synthetic.

## Start the application

### Docker Compose

From the repository root:

```powershell
docker compose up --build -d
```

Open `http://localhost:8080`. On first start the API creates SQLite tables, seeds the demo records once, and trains the models if valid saved artifacts are missing. The dashboard and API ports are bound to localhost.

### Local development

In one PowerShell terminal:

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m app.start
```

In a second terminal:

```powershell
cd frontend
npm.cmd install
npm.cmd run dev
```

Open the Vite URL (normally `http://localhost:5173`). `python -m app.start` prepares the database and model artifacts and then starts FastAPI. The Vite `/api` proxy connects the browser to it.

## Five-minute talk track

### 1. Frame the problem

“Skill Pluse brings assessment, attendance and assignment signals into one training overview. It helps a trainer decide which records or learners to review. It is a demonstration product using synthetic data.”

Point to the synthetic-data notice and API status badge at the top of the dashboard.

### 2. Show the cohort overview

Start on **Overview**. Explain the active learner count, score average, attendance rate and assignment completion. Use the batch selector to compare all cohorts with **Data Analytics · Jan 2025** (`BATCH-02`), then switch the trend control to **Recent 2**.

Explain that the 70% benchmark is a descriptive review threshold. It is not the ML prediction threshold and it does not determine learner outcomes.

### 3. Open a learner profile

Choose **All batches**, navigate to **Learners**, and search for `STU-091` (synthetic learner Aarav Desai). Open the profile to see recent assessment history, the trainer-assist support estimate and its strongest contributing signals, a score-based practice suggestion, and the cluster grouping.

For the current checked-in demonstration artifacts, this example is flagged at approximately 62%. Values can change if the synthetic dataset or model is regenerated. Point out the notice: the estimate is synthetic, is not calibrated on real learners and must not drive placement or certification.

### 4. Review skill gaps and import scores

Open **Skill gaps** to compare assessed skill averages against the descriptive benchmark. In **Assessments**, search and paginate the current results. To demonstrate score entry, expand **Create an assessment**, select a batch and create a checkpoint inside that batch's date range. Select it in **Import assessment scores**, download its CSV template, fill a few fictional scores, and import the file. The page refreshes and lists the new assessment results. The import rejects the whole file if any populated row has an invalid ID, batch, duplicate or score.

### 5. Finish with reports and evaluation

Open **Reports**. Show the batch comparison, Logistic Regression precision/recall/F1 and confusion matrix, then use **Export batch report** to download the CSV. State that the held-out results describe only the generated sample and are not evidence of real-world model performance.

## Questions you may be asked

- **Where does data live?** SQLite is used for the local/demo installation. Docker Compose persists it in the `skillpulse_data` named volume.
- **What if there is too little data?** The support endpoint returns `insufficient_data` and no probability estimate when there are not enough assessment checkpoints, attendance sessions or assignments.
- **How was the model evaluated?** It uses a stratified 75/25 holdout split. The preprocessing scaler is fitted on training rows only; the test rows are held back for reported precision, recall, F1 and confusion matrix.
- **Can the model decide who is placed or certified?** No. The signal only supports trainer review. It must not make placement or certification decisions.
- **Can this deployment store real learner data?** Not yet. Authentication and authorization are not implemented. Keep this deployment local and synthetic-data-only.

## Troubleshooting during a demo

- If the app shows **Offline demo**, confirm FastAPI is available at `http://127.0.0.1:8000/api/health`, then use **Retry** in the dashboard.
- If startup reports unavailable or stale model artifacts, run `python -m app.ml.train` from `backend/`, or restart the app with `python -m app.start` so it can ensure the artifacts.
- If Docker ports are busy, set `SKILLPULSE_WEB_PORT` and/or `SKILLPULSE_API_PORT` before `docker compose up --build -d`; see `phase-9-deployment.md`.
- If learner signals are insufficient, choose a synthetic profile with more historical activity. Do not interpret a missing estimate as “on track.”
